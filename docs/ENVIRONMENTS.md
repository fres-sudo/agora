# Environments, Flavors & Feature Flags

This guide covers how Agora is configured per environment, how the build
flavors map to native apps, and how the free-vs-premium feature gating works.

There are three independent axes:

| Axis | Controls | Owned by | Set via |
|---|---|---|---|
| **Flavor** | native app id / name / icon | `flutter_flavorizr` + `package:config` | `--flavor` |
| **Environment** | API/WS URLs, bootstrap mode, logging | `package:config` (`AppConfig`) | `--dart-define-from-file=config/<env>.json` |
| **Tier** | free vs premium feature gating | `package:feature_flags` | `TIER` key in the env file (overridable at runtime) |

> A flavor is **not** a tier. The production flavor ships with `TIER=free` by
> default; a paid subscription raises the tier at runtime. Keeping them separate
> avoids a combinatorial explosion of native build types.

---

## 1. Flavors

| Flavor | Android applicationId | iOS bundleId | App name |
|---|---|---|---|
| `dev` | `space.fres.agora.dev` | `space.fres.agora.dev` | Agora Dev |
| `staging` | `space.fres.agora.stg` | `space.fres.agora.stg` | Agora Staging |
| `prod` | `space.fres.agora` | `space.fres.agora` | Agora POS |

Flavors are generated by `flutter_flavorizr` from `apps/agora/flavorizr.yaml`.

### (Re)generating native flavor config

Run from `apps/agora`, with a **restricted** processor set so the hand-written
`lib/main.dart` and `lib/app/app.dart` are not overwritten by the
`flutter:app` / `flutter:pages` / `flutter:main` processors:

```bash
cd apps/agora
fvm flutter pub run flutter_flavorizr \
  -p android:androidManifest,android:flavorizrGradle,android:buildGradle,android:dummyAssets,android:icons,flutter:flavors,ios:podfile,ios:xcconfig,ios:buildTargets,ios:schema,ios:dummyAssets,ios:icons,ios:plist,ios:launchScreen,ide:config
cd ios && pod install && cd ..
```

This regenerates `apps/agora/lib/flavors.dart` (the `Flavor` enum / `F` helper)
and the native Android/iOS build configs. `package:config`'s `AppConfig`
remains the authoritative source for runtime values; `F` is only used so the
native schemes exist.

## 2. Environment files

Per-environment values live in `config/*.json` and are read at **build time**
through `AppConfig.fromEnvironment()`. Only the `*.example` files are committed;
copy them to the real (git-ignored) names:

```bash
for e in local dev staging prod; do
  [ -f "config/$e.json" ] || cp "config/$e.json.example" "config/$e.json"
done
```

See [`config/README.md`](../config/README.md) for the full key reference.

### Bootstrap modes

`BOOTSTRAP_MODE` selects how `main.dart` boots:

- **`local`** — fully offline. Local Drift DB only. No Dio base URL, no sync
  engine, no websocket. This is the shippable free festival tier.
- **`hybrid`** — backend-connected. The Dio base URL is set from
  `API_BASE_URL`, and the sync-engine/websocket seam (`WS_BASE_URL`) is prepared
  for the paid tier (started once an auth token exists — see
  `FESTIVAL_POS_TASKS.md` P9-2).

## 3. Feature flags (free vs premium)

`package:feature_flags` resolves a `SubscriptionTier` and exposes a
`FeatureFlags` object that answers `isEnabled(Feature.x)`.

```dart
// In a widget:
if (context.featureFlags.isEnabled(Feature.kitchenSync)) {
  // show / start the paid capability
}

// Reactively:
BlocBuilder<FeatureFlagsCubit, FeatureFlags>(
  builder: (context, flags) => flags.isEnabled(Feature.cloudReports)
      ? const CloudReportsButton()
      : const SizedBox.shrink(),
);
```

### Tiers and gated features

| Feature | free | paidBasic | paidPro |
|---|---|---|---|
| `kitchenSync` | — | ✓ | ✓ |
| `multiTerminalSync` | — | ✓ | ✓ |
| `cloudReports` | — | ✓ | ✓ |
| `aiReportSummary` | — | ✓ | ✓ |
| `aiDietaryFilter` | — | ✓ | ✓ |
| `aiUpsellNudge` | — | — | ✓ |
| `aiWaitingTimeAlert` | — | — | ✓ |
| `aiKitchenPrioritisation` | — | — | ✓ |
| `aiDemandForecast` | — | — | ✓ |

Always-free capabilities (catalog, cart, thermal printing, local reports,
inventory) are never gated and intentionally have no `Feature` entry.

### Resolution order

1. A persisted runtime override (`FeatureFlagsCubit.setTier(...)`) — useful for
   QA to exercise paid features without a backend.
2. The compile-time default from `TIER` in the active env file.

Default is always `free`, so the app degrades safely offline.

## 4. Running

### VS Code

Use the **Run and Debug** panel — `.vscode/launch.json` ships these configs:

- Agora — Local (free, offline)
- Agora — Dev (hybrid)
- Agora — Staging (hybrid)
- Agora — Prod  /  Agora — Prod (release)
- Agora — Dev (profile)

### CLI (melos)

```bash
melos run run:local      # offline free tier
melos run run:dev        # dev backend, all features
melos run run:staging    # staging backend
melos run run:prod       # production
```

### CLI (manual)

```bash
cd apps/agora
fvm flutter run --flavor dev --dart-define-from-file=../../config/dev.json
```

### Building artifacts

```bash
cd apps/agora
fvm flutter build apk    --flavor prod --dart-define-from-file=../../config/prod.json --release
fvm flutter build ipa    --flavor prod --dart-define-from-file=../../config/prod.json --release
```
